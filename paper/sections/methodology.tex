\section{Generalized Specimen-Centric Data Protocol (SCDP)}

To address the methodological deficiencies of ad-hoc dataset creation in physical computer vision domains, we propose the **Specimen-Centric Data Protocol (SCDP)**. SCDP is a generalized data governance framework that standardizes every stage of dataset lifecycle management---from physical sample acquisition and immutable metadata storage to automated group-disjoint partitioning and cross-split auditing. Figure~\ref{fig:scdp_workflow} illustrates the five sequential phases of the SCDP framework.

\subsection{Phase 1: Physical Acquisition Logging and Provenance Standards}
Existing dataset collection pipelines routinely discard sample provenance, recording only target class labels. SCDP mandates that every image acquisition event must be bound to immutable physical provenance attributes at the moment of capture:

\begin{enumerate}[label=\textbf{(\arabic*)}, leftmargin=*]
\item \textbf{Physical Specimen Identifier ($\mathrm{SID}$)}: A unique, deterministic alphanumeric identifier assigned to each distinct physical sample (e.g., individual wood log block, biological core, patient sample). All images harvested from the same physical entity inherit identical $\mathrm{SID}$ tags.
\item \textbf{Acquisition Session Identifier ($\mathrm{AID}$)}: An identifier tracking photo capture sessions, camera hardware settings, operator IDs, and environmental lighting conditions.
\item \textbf{Surface Preparation State}: Metadata recording mechanical treatment (e.g., saw cut, planed surface, sanded grit level, anatomical cross-section orientation).
\end{enumerate}

By capturing physical provenance at harvest time, SCDP establishes an auditable chain of custody that prevents accidental physical source co-occurrence during downstream partitioning.

\subsection{Phase 2: Immutable Storage Schema and Data Organization}
To decouple dataset management from transient local directory structures or arbitrary file naming conventions, SCDP replaces unindexed file trees with an **Immutable Manifest Architecture**. Let $\mathcal{X} = \{x_i\}_{i=1}^{M}$ denote the dataset of $M$ image observations, and let $\mathcal{S} = \{S_j\}_{j=1}^{N}$ represent the set of $N$ physical specimens ($M \gg N$). Every image $x_i$ is registered in a version-controlled manifest file containing the schema attributes outlined in Table~\ref{tab:manifest}.

The physical source mapping function $s: \mathcal{X} \to \mathcal{S}$ is explicitly defined via the manifest field \texttt{specimen\_id}: $s(x_i) = S_{x_i.\texttt{specimen\_id}}$. The manifest is cryptographically hashed (SHA-256) to ensure full auditability and reproducibility.

\subsection{Phase 3: Automated CEGS-Split Partitioning Algorithm}
\label{sec:cegs_split}
Given an immutable manifest, dataset partitioning must guarantee absolute specimen disjointness while preserving per-class sample balance and representation difficulty. Standard `GroupKFold` enforces group isolation but ignores class distribution, often producing severe sample size imbalance or missing minority classes.

To solve this multi-objective optimization problem, we introduce **Class-wise Embedding-Guided Specimen Split (CEGS-Split)**. For each class $c \in \{1, \dots, C\}$, CEGS-Split extracts specimen feature centroids using a frozen feature backbone $f_\theta$:
\begin{equation}
h_j = \frac{1}{|S_j|} \sum_{x_i \in S_j} f_\theta(x_i), \quad S_j \in \mathcal{S}_c,
\end{equation}
where $\mathcal{S}_c = \{S_j \in \mathcal{S} : y(S_j) = c\}$ is the set of specimens belonging to class $c$.

CEGS-Split evaluates seven distinct feature-space allocation strategies per species:
\begin{enumerate}[label=\textbf{Strategy \arabic*:}, leftmargin=*]
\item \textbf{Fixed Mahalanobis Stratification}: Computes the class mean $\bar{h}_c$ and static covariance matrix $\mathbf{\Sigma}_c$, allocating tail-end Mahalanobis outliers to held-out test splits to enforce evaluation difficulty.
\item \textbf{Iterative Mahalanobis Allocation}: Re-estimates the dynamic class covariance matrix after assigning each specimen, preventing outlier masking in skewed distributions.
\item \textbf{Hierarchical Agglomerative Partitioning}: Applies Ward's linkage clustering on specimen centroids $\{h_j\}$ and assigns intact sub-trees to splits, preserving natural cluster structures.
\item \textbf{Cosine Feature Graph Partitioning}: Constructs a $k$-nearest neighbor similarity graph across specimen centroids and finds spectral min-cut partitions to minimize cross-split similarity.
\item \textbf{Adversarial Density Validation}: Trains an auxiliary domain classifier (e.g., LightGBM) to distinguish candidate splits, selecting partitions where adversarial $\mathrm{AUC} \to 0.50$ (maximum distributional overlap).
\item \textbf{Stratified Group Allocation}: Extends multi-objective GroupKFold optimization to balance exact per-species target sample ratios while enforcing specimen disjointness.
\item \textbf{Agglomerative Stratified Banding}: Combines hierarchical clustering with distance-band stratification (Near, Mid, Far shells from class centroid), ensuring representative split compositions.
\end{enumerate}

For each species $c$, the optimal strategy $m^*$ is selected automatically by minimizing cross-split nearest-neighbor cosine similarity on candidate test partitions:
\begin{equation}
m^* = \arg\min_{m} \frac{1}{|\mathcal{D}_{\mathrm{test}}^{(m,c)}|} \sum_{x_i \in \mathcal{D}_{\mathrm{test}}^{(m,c)}} \max_{x_j \in \mathcal{D}_{\mathrm{train}}^{(m,c)}} \left( \frac{z_i^T z_j}{\|z_i\|_2 \|z_j\|_2} \right).
\label{eq:strategy_selection_formal}
\end{equation}

\subsection{Phase 4: Cross-Split Near-Duplicate and Proximity Audit}
Following split generation, CEGS-Split audits the maximum cross-split feature proximity for every test specimen $S_j \in \mathcal{S}_{\mathrm{test}}$:
\begin{equation}
r_j = \max_{S_k \in \mathcal{S}_{\mathrm{train}}} \left( \frac{h_j^T h_k}{\|h_j\|_2 \|h_k\|_2} \right).
\label{eq:nn_audit_formal}
\end{equation}

Specimens falling in the upper 95th percentile of $r_j$ are flagged for manual provenance verification. If physical harvest logs indicate that two high-similarity specimen IDs originate from the same physical tree trunk, the manifest is corrected and the split regenerated. If physical logs confirm distinct biological origin, the pair is retained as a valid intra-species benchmark challenge.

\subsection{Phase 5: Auditable and Leak-Free Downstream Evaluation Protocol}
Under SCDP, downstream model evaluation is conducted on frozen manifest partitions ($\mathcal{D}_{\mathrm{train}}, \mathcal{D}_{\mathrm{val}}, \mathcal{D}_{\mathrm{test}}$). Once locked, test sets are strictly held out from hyperparameter optimization, threshold tuning, or feature scaler fitting. Performance metrics reported under SCDP reflect genuine model capacity to recognize unobserved physical entities.
